Auto Mode Specification

本書は、ポケモン対戦ログ（Pokemon Battle Log）における「オートモード（Switch実機映像の全自動対戦検知・選出追跡・自動記録システム）」の完全なアーキテクチャ、状態遷移、認識座標パラメータ、およびアルゴリズムを定義する公式仕様書です。

⚠️
運用ルール（重要）: 仕様書とコードの完全同期義務
今後オートモードのコード（scripts/auto_mode_controller.js, scripts/recognition_engine.js 等）を修正・改修する場合は、必ず本仕様書（Markdown版および本HTML版）を同時に更新してください。コードとドキュメントの乖離は一切認められません。
01

全体アーキテクチャと処理フロー

Switch実機映像（1920×1080、16:9）を毎秒約2〜3回（350ms間隔）キャプチャし、ステートマシンによって現在のゲーム画面のフェーズを判定しながら、相手パーティ、相手トレーナー名、自分・相手の選出（4体）、勝敗を自動取得して記録フォームに入力します。

    IN_GAME --> FINISHED: 勝敗ボール検知 (Win/Lose確定)
    FINISHED --> WAITING_MATCHING: ログ自動保存完了 / 次の対戦待ち (8秒待機ガード)

1.1 オートモード起動・停止とリソース管理

▶️ 起動シーケンス (startAutoMode)
  1. navigator.mediaDevices.getDisplayMedia でSwitchキャプチャ映像ストリームを取得。
  2. <video> にストリームをバインドし、1920×1080バッファキャンバスを準備。
  3. Web Worker群（OpenCVワーカー、カタカナOCR、汎用OCR）をオンデマンドで初期化。
  4. ステートマシンを WAITING_MATCHING に設定し、350ms間隔の検知ループを開始。
⏹️ 停止シーケンス (stopAutoMode)
  1. isAutoRunning = false をセットし、定期ループタイマーを破棄。
  2. 映像ストリームの全トラックを停止 (track.stop()) してキャプチャ権限を解放。
  3. ステートマシンを IDLE に戻し、右下VSバーを初期化。

1.2 対戦形式とBO3モードの扱い (BO1専用固定仕様)

📌
ランクバトル (BO1) 専用の完全自動フロー
オートモードは、Nintendo Switch のランクバトル（1試合完結型：BO1）専用として動作仕様が確定・固定されています。
1試合が終了して勝敗が確定すると、即座に対戦ログが1件として自動保存され、履歴画面へ自動遷移します。
※BO3 (3本勝負) 大会等で対戦ログをつける場合: アプリの通常モード（手動記録画面のBO3機能）をご利用ください。

Y座標間隔（125.9 vs 126.0）に関する補足 (pamo3 原典仕様)
相手アイコンの間隔が 125.9 に対し属性アイコンが 126.0 となっているのは、pamo3 の原典ソースコード（aBO.cKJ および byN.aoK）と全く同一の実装仕様です。

04

前処理とOCR・照合アルゴリズム

4.1 ネームプレートOCR前処理 (cropForDispatchOcr)

  1. 原寸切り出し: 指定座標 (x, y, w, h) を Canvas に切り出し。
  2. 2倍拡大描画: Tesseract の認識精度を最大化するため 2x に拡大。
  3. 高コントラスト白文字二値化: 輝度 Y = 0.299R + 0.587G + 0.114B。Y ≥ 170 または (R > 165 ∧ G > 165 ∧ B > 165) のピクセルを文字（黒 0）、その他を背景（白 255）へ変換。
  4. Tesseract.js OCR: カタカナ・ひらがな辞書を用いて高速認識を実行。

4.2 ポケモン名ファジーマッチング

  • OCR結果テキストから空白・改行を除去。
  • 照合プール（相手なら rivalPartyNames、自分なら myPartyNames）とレーベンシュタイン編集距離を計算。
  • フォルム名（メガ、原種等）の正規化ベース名とも比較。
  • 編集距離 ≤ 2 の場合、一致として採用。
  • 相手側で手持ちと一致しなかった場合、全体マスタ（POKEMON_LIST）からフォールバック検索。

4.3 交代・繰り出し追跡ロジック (ダブルバトル4枠)

  • 各陣営の選出リスト（detectedDispatchedMe, detectedDispatchedRival）は配列として管理。
  • 出撃・HPバー検知で新しいポケモン名が認識された場合、まだリストに含まれていなければ次のスロット（3体目、4体目）として自動追加。
  • 上限（4体）に達した陣営はOCR監視を自動停止し、CPU負荷を最小化。

4.4 先発 (1・2枠) と後発 (3・4枠) のスロット決定規則

⚔️ 出撃演出検知時 (先発スロット0, 1)
出撃演出（DISPATCH_DOUBLE のインデックス 0, 1）で検知された2体は、確定で「先発1」「先発2」のスロットに割り当てられます。
🔄 対戦中HPバー・交代時 (後発スロット2, 3)
先発枠が埋まっている状態で新しく検知されたポケモンは、順次「後発1 (スロット2)」「後発2 (スロット3)」へと割り当てられます。
👆 手動選出時
ユーザーがタップした順序（1〜2番目が先発、3〜4番目が後発）がそのままスロットへ反映されます。

4.5 フォルム違い・メガシンカ・リージョンフォームの照合規則

  • 実機ネームプレートの特性: 実機の出撃ネームプレートにはフォルム名やメガシンカの文字は表示されず、ベース名（例:「リザードン」「オーガポン」「キュウコン」）のみが表示されます。
  • 正規化ベース名照合 (_normalizeBasePokeName): ポケモン名に含まれる括弧情報（例:「リザードン(メガX)」「オーガポン(かまど)」「キュウコン(アローラ)」）を除去し、ベース名同士で一致判定を行います。
  • 手持ち内特定フォルムとの自動紐付け: 見せ合いで見つかった特定フォルム（例: オーガポン(かまど)）が相手手持ちにあれば、OCRで「オーガポン」が読まれた際に自動的に「オーガポン(かまど)」と特定して選出スロットへ反映します。
  • 同種族ポケモンの別フォルム存在時の扱い (公式ランクバトル規約準拠): 公式ダブルバトル（ランクバトル/公式大会）のレギュレーション上、全国図鑑番号が同一のポケモンの重複登録・選出は禁止されています。したがって、相手パーティ内に同一種族の別フォルム（例: 原種キュウコンとアローラキュウコン）が同時に重複登録されるケースの例外処理は不要（ランクバトル規約準拠）として仕様を固定しています。

4.6 マスタリストフォールバック照合（手持ち外の自動救済）

  • 相手の出撃OCR結果が見せ合いで取得された手持ち6体と一致しなかった場合（見せ合いの誤認識や手持ち欠落時）、window.POKEMON_LIST（全ポケモンマスタ）全体を対象にレーベンシュタイン距離照合を実行します。
  • レーベンシュタイン距離 ≤ 2 の一致候補が見つかった場合、そのポケモン名を採用して選出スロットに自動登録します。

Switch 1920×1080 画面において、左下の選出完了ボタン（「[ > ◓ 4/4 選出完了 ]」）の緑色フレームの左端にある、モンスターボールの丸いアイコンです。

📍 座標とサイズ

⚡ フェーズ判定の役割

  • score < 0.35: 見せ合い終了（対戦開始待機へ移行）
06

UI画面遷移および入力フォーム連携仕様

  • オートモード開始時: window.showPage('record') を呼び出し「記録する」タブへ自動切替。対戦ルールをダブルバトル（選出4体）に固定。
  • 見せ合い画面検知時 (MATCHING): 相手6体をスロットへ入力しアイコン更新。相手トレーナー名を入力。相手選出ドロップダウンを再構築。
  • 対戦中 (IN_GAME): 出撃・HPバー検知で自分・相手の選出（最大4体）をバッジ・ドロップダウン・下部VSバーへ自動反映。
  • 試合終了時 (FINISHED): 勝敗ボール検知に基づき勝ち/負けボタンを自動選択。saveRecord() で自動保存。保存完了の約1.2秒後に自動的に「履歴 (history)」タブへ画面遷移。
07

手入力修正（マニュアルオーバーライド）への対応仕様（各フェーズ別）

オートモード稼働中、ユーザーがUIフォームや選出バッジを手動操作（修正・先行入力）した場合の、システム各フェーズでの詳細対応仕様です。

🛡️
3大全体基本原則 (Core Principles)
1. ユーザー操作の絶対優先: 自動画像検知の結果よりも、ユーザーが直接入力・選択した内容が常に最優先。
2. 手動確定枠の保護 (Non-Destructive): ユーザーが確定させた値を自動検知ループが勝手に上書き・消去することは固く禁止。
3. 部分的手動入力の協調補完: 先発2体のみ手動入力した場合、自動検知は未確定の空きスロット（3体目・4体目）にのみ補完。

    end

    subgraph P2[MATCHING: 見せ合い画面中 60〜90s]

    end

各フェーズでの詳細挙動

① マッチング待機 (WAITING_MATCHING)
自分のパーティ切り替え時、this.myPartyNames を即座に再取得。VSバーおよび出撃管理リストは初期状態を維持。
② 見せ合い (MATCHING)
相手パーティ修正: 入力検知で照合候補を即時更新し、選出グリッドを再描画。
自分の選出先行入力: 1〜4タップで detectedDispatchedMe へ即時同期し、VSバーのボールがポケモンアイコンに変身。
自動上書き防止: 相手認識は突入時の1回のみ。ループで手入力を上書きしない。
③ 対戦開始待機 (WAITING_GAME_START)
見せ合い中に入力された手動選出をそのまま維持（対戦開始時のリセット廃止）。最新手入力値を照合辞書に固定。
④ 対戦中 (IN_GAME)
遅延手入力修正: 対戦中の相手パーティ変更も即座に照合プールへ反映。
手動選出保護: 手動選択された枠は自動検知で消去・上書きされない。空きスロットのみに自動検知結果を補完。
⑤ 試合終了 (FINISHED)
勝敗手動選択優先: ユーザーが手動で押した勝ち/負けを最優先し、画像認識の自動判定での上書きをブロック。空枠のみ自動補完。

7.4 通信エラー・回線切断時の手動リカバリー仕様 (案B)

🔄
ワンクリック手動リセットと入力データ保護
対戦相手の回線切断、自身の通信エラー、相手の降参による即時終了等により、勝敗ボール（WIN_BALL）が表示されずロビーへ戻った場合は、右下VSバー中央の「待機へリセット」ボタンまたは映像下部バーの「🔄」ボタンを押すことで、即座に WAITING_MATCHING へフェーズを復帰できます。
リセット時も、見せ合いや対戦中に取得・入力された相手パーティや選出データは一切消去されずそのまま保持されるため、ユーザーは手動で勝敗ボタンを選択し、「対戦ログを保存」を押すことで安全に記録を保存完了できます。

下部VSバー（出撃ポケモン表示）のアニメーション仕様 (ピコピコ防止仕様)

画面下部に配置された出撃ポケモン表示バー（自分4スロット・相手4スロット）におけるポップインアニメーション規則および、検知ループによる過度な点滅・ピコピコ現象の防止仕様です。

8.1 意図した挙動とアニメーション規則

  • モンスターボールからポケモンへの変身 (popIn): 対戦開始時、VSバーの全8枠はモンスターボールアイコン（52px）で初期化されます。出撃演出やHPバー検知、または手動選出によりポケモンが特定された瞬間、そのスロットのポケモンが1回だけ「ポンッ」と跳ねて拡大・着地するポップインアニメーション (animation: popIn 0.35s cubic-bezier(0.175, 0.885, 0.32, 1.275)) が再生されます。
  • アニメーション再生後は静止表示を維持: 一度出撃が確定して表示されたポケモンは静止状態を維持し、ユーザーが快適に確認できるようにします。

8.2 毎フレーム点滅・ピコピコ現象の防止機構 (バグ防止ガード)

⚡
現象の背景と防止ガード実装 (updateVsBarSlot)
対戦中、出撃ポケモンの検知ループは約350〜400msごとに高頻度で実行されます。もしすでに表示中のポケモンであっても毎回DOM（innerHTML）を再生成してしまうと、350msごとに毎フレーム popIn アニメーションがリセットされて最初から再生され続け、ポケモンアイコンがピコピコと連続して点滅・拡大縮小を繰り返す不具合（意図しない挙動）が発生します。
【防止仕様】 各スロットのDOM要素の dataset.currentPokemon に現在描画されているポケモン名を保持し、updateVsBarSlot(role, slotIndex, pokemonName) 実行時に dataset.currentPokemon === pokemonName であればDOM再描画とアニメーション再起動を即座にスキップします。これにより、新規出撃・交代・手動選出変更があった瞬間のみ1度だけ軽快なアニメーションが再生され、以降は一切ピコピコしない安定した表示が保証されます。
09

改修・保守ルール

  1. 引数ルールの遵守: recognitionEngine.recognize をオートモードから呼び出す際は、必ず 第4引数に true (isSwitch1080p) を渡すこと。渡さないと iPhone 用座標系（X=1955等）が使用され認識が全滅します。
  2. ステートマシンのフライング防止: 画面認識結果以外の安易な短い固定タイマーだけでフェーズを強制遷移させてはならない。必ずゲーム画面のUIマーク（ボールマーク、VSロゴ、HPバー等）の有無を基準にし、チャタリング防止のための連続判定（デバウンス）を設けること。
  3. 手入力値の非破壊原則: いかなる自動認識・自動更新処理も、ユーザーが明示的に手入力したフォーム値や選出状態を消去・上書きしてはならない。必ず手動入力値をベースとして協調動作させること。
  4. 本仕様書の両ファイル同期更新ルール (必須): 今後オートモードの仕様に変更が入った際は、docs/AUTO_MODE_SPECIFICATION.md と docs/AUTO_MODE_SPECIFICATION.html の両方を必ず同時に修正・更新すること。
